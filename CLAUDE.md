# Class Management System — Agent Instructions

## Before You Do Anything

Read the project structure carefully before implementing. This is a Next.js + Convex app.

## Stack
- **Frontend:** Next.js 15 (App Router), Tailwind CSS, hosted on Vercel
- **Backend:** Convex (functions, database, cron, file storage)
- **WhatsApp:** Twilio
- **Auth:** Custom admin auth (username/password, stored in Convex)

## Key Conventions
- Convex schema is in `convex/schema.ts` — update it first when adding new fields/tables
- Convex functions go in `convex/` directory (queries, mutations, actions)
- Frontend pages go in `app/` using Next.js App Router
- Admin portal is at `app/admin/`
- Participant-facing pages: `app/participant/[participant_id]/` and `app/terms/`
- Use `v.optional(...)` in Convex schema for optional fields
- Run `npx convex dev` to sync schema changes (but don't run it in implementation — just write the code)
- Tailwind for all styling — no custom CSS unless necessary

## ⚠️ Critical: Two Convex Deployments — ALWAYS Use --prod

This project has **two separate Convex environments** that are completely isolated:

| Deployment | URL | Purpose |
|---|---|---|
| **Production** | `colorless-raven-523.convex.cloud` | Live app — what users see at `class-management-system-teal.vercel.app` |
| **Dev** | `graceful-mole-393.convex.cloud` | Local dev/test only |

**The golden rule: any data (purchases, participants, sessions, etc.) created on dev is INVISIBLE to the production website, and vice versa.**

### Running Convex commands

Without `--prod`, ALL `npx convex run` and `npx convex function-spec` commands target **dev** by default:

```bash
# ❌ WRONG — runs against dev, data invisible to prod website
npx convex run testPurchase:createTestPurchase '{...}'

# ✅ CORRECT — runs against production
npx convex run testPurchase:createTestPurchase '{...}' --prod
```

### Deploying Convex functions

`npx convex deploy --yes` deploys to production (`colorless-raven-523`) because `.env.local` has `CONVEX_DEPLOYMENT=dev:graceful-mole-393` and `deploy` always promotes to the prod counterpart.

But **always verify** by checking the output line: `Deploying to https://colorless-raven-523.convex.cloud...`

### Checking what's deployed

```bash
# List all prod functions
npx convex function-spec --prod

# List all dev functions (default)
npx convex function-spec
```

### env.local warning

`vercel env pull` **overwrites `.env.local`** and removes the Convex deployment config. After any `vercel env pull`, restore `.env.local` with:
```
CONVEX_DEPLOYMENT=dev:graceful-mole-393
```
